CLAIM: Signal you are starting work. Transitions state to 'in_progress' and records your claim (agent_type +
metadata). Returns full feature details; this is your spec to implement. IMPORTANT: You MUST call this tool when a
user asks you to implement, work on, or build a feature, even if you just created the feature or already have
context. Also handles implemented features with pending changes (desired_details set by a human edit), transitioning
implemented → in_progress so you can implement the requested changes. Do not change the feature's target version
during implementation.

SPEC GATE: Blocks if a leaf feature has no `details` or has no testable acceptance criteria (checkbox items,
assertion verbs, or Gherkin Then lines). You must write a spec with verifiable criteria using update_feature.
Use force=true to bypass this check for features that genuinely have no testable behavior (e.g., documentation).

BLOCKED GUARD: Rejects features in `blocked` state and features whose ancestor feature set is blocked. Returns the
list of blocking features that must reach 'implemented' before this feature can be started.

CONCURRENCY: If another agent has claimed this feature, returns a conflict warning with details (who claimed it,
when, branch info). Use force=true to override the claim.

GIT BRANCH: Auto-creates and checks out a `feature/{slug}` branch based on the feature title. Best-effort; does
not fail if no git repo or no commits exist yet.

LEAF FEATURES ONLY: This tool rejects feature sets (parents with children). If you need to work on an area that has
children, start one of its child features instead.

COMPLETION CONTRACT: The response includes a reminder of the mandatory sequence after implementing:
prove_feature → update_feature → complete_feature. It also includes testing guidance based on the project's
spec template and testable acceptance criteria count.
